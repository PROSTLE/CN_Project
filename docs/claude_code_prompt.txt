You are building GLASSWALL, an explainable AI firewall, in this private
repository. The specification is in docs/:
  prd.txt, trd.txt, database_schema.txt, ui_ux_requirements.txt,
  design_flow.txt, tech_flow.txt, implementation_plan.txt.
Read the docs relevant to the current phase before writing code. Where docs
conflict, prd.txt > trd.txt > others; ask me instead of guessing.

Environment: Windows 11 + Docker Desktop (WSL2). All Linux work happens in
containers. The gateway container is privileged and loads eBPF. Do not
assume native Linux on the host.

HARD RULES
1. No hardcoded learned values. k, alpha, tau_lo, tau_hi, fidelity
   thresholds, canary duration, rollback limit, rate limits, ACI gamma and
   alpha_target are read from config/glasswall.yaml or the active
   config_versions row. [LEARNED] keys are null in the template and filled
   only by scripts/calibrate.py from a validation run. Startup must fail
   loudly if a required [LEARNED] value is missing.
2. No fabricated results. Never write metric values, sample numbers or
   "example" accuracies into code, UI, README or reports. UI shows empty
   states when no data exists. Tests may use synthetic fixtures that are
   clearly named as fixtures and never shown as results.
3. No hallucinated APIs. Before using a library function (cilium/ebpf, ncps,
   interpret, shap, mapie, river, tpm2-pytss, dice-ml), check its installed
   version's real signature (help(), go doc, or the source in site-packages
   / module cache). If unsure, say so and verify. Pin versions in lockfiles.
4. Do not use raw IP addresses or ports as model features. Add a test that
   enforces this.
5. Hot path explainers are exact/deterministic only (TreeSHAP, EBM terms,
   CfC integrated gradients). LIME/KernelSHAP are offline only.
6. The LLM narrator is never in the decision path.
7. The safety allow-list (from config) must be checked first in the kernel
   and refused by agent, compiler and API.
8. The datapath never sees a half-written rule set: write inactive array,
   flip active index in one map update.
9. Ledger tables are append-only (trigger + grants).
10. Confidentiality: never push to a public remote, never create public
    gists/pages, never paste internals into external services. Do not
    commit data/, models/, keys or .env.
11. Small, reviewable steps. After each step run the tests/commands that
    prove it works and show me the real output. If something fails, report
    the failure honestly; do not claim success.
12. Label what you measured with its environment (WSL2, xdpgeneric/tc/nft,
    swtpm). Never claim line rate.
13. Match the repo layout in implementation_plan.txt section 1. Keep code
    style consistent; type hints in Python, gofmt for Go, strict TS.
14. When a design choice is not in the docs, pick the simplest option, mark
    it with a "# PROPOSED:" comment, and list it in your summary.
At the end of every phase: list files changed, commands run with results,
open issues, and an INVENTION_LOG.md entry draft if Inventions 1-5 were
touched (I will add names/dates).
